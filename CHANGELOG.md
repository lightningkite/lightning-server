# Changelog

All notable changes to Lightning Server are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Each release groups entries under:

- **API** — public surface changes (added / changed / removed types and functions).
- **Behavior** — runtime behavior changes that do not alter the public surface.
- **Tests** — test-only additions and changes.
- **Build** — build-script, dependency, and tooling changes.

## [Unreleased]

### API

- Added an `auth` parameter to `JsonRpcHandler`, defaulting to `noAuth`. It is asserted before the body is read, so a caller that fails it gets the HTTP 401 or 403, never a parse, version or method-not-found error. Methods still assert their own `auth`.
- **Behavior:** the Kotlin SDK (`FetcherSdk`) starts each generated file with `@file:OptIn(...)` listing the `@RequiresOptIn` markers on the classes it names (endpoint inputs, outputs, path arguments and their type arguments), so apps no longer opt in module-wide. `typed` now depends on `org.ow2.asm:asm` to read those markers, which are BINARY-retained and invisible to reflection.
- Added `AuthEvent.FactorChanged(method, principalType, principal, change)`, with `change` one of `Added`, `Replaced`, `Removed`, so an app can notify a user when a way into their account changes: install an `AuthEventListener` that emails them. It is raised after the write for a password set, changed, or disabled; a TOTP secret confirmed (an unconfirmed setup doesn't count), replaced, or disabled; a WebAuthN credential or known device added or disabled; and backup codes reset or cleared. Changes are seen through each method's `modelInfo` signals, so REST edits to `/secrets` and `/credentials` and app writes through `modelInfo` are reported too. A password change or confirmed TOTP replacement is one `Replaced`, not an add and a remove. As with every auth event, a listener that throws is logged and the change stands. `request` is `null` except for backup codes. `AuthEventLog` records it (type `FactorChanged`, with the new `factorChange`). **Breaking** for exhaustive `when`s over `AuthEvent`.
- **Breaking: removed the sub-session endpoint.** `SessionManager.createSubSession` (`POST sub-session`), its input `SubSessionRequest`, and `subsession` in `AuthClientEndpoints` / `LiveAuthClientEndpoints` are gone: a stolen access token could mint a long-lived refresh token through it. Sub-sessions themselves stay: create them server-side with the new `SessionManager.newSubSession(parent, label, scopes, expires)`, which applies the endpoint's rules (scopes and expiration within the parent's, inherited authentication and stale time, terminated with the parent).
- Added a way for web clients to keep the refresh token out of page scripts' reach, in `SessionManager` (and so `AuthEndpoints`): `POST token/set-cookie` (`setRefreshTokenCookie`, refresh token in the body) validates the token and sets it as the `RefreshToken` cookie (`HttpOnly; Secure; SameSite=Strict`, `Path` limited to `token/cookie` under the public URL's path, expiring with the session). It accepts only an `application/json` body, so a cross-site form can't plant a session. For local development over plain http, `refreshTokenCookieSecure = Runtime { false }` (on `SessionManager` and `AuthEndpoints`) drops `Secure`. `POST token/cookie` (`getTokenFromCookie`, no body) returns an access token for it, or 401. Log in with `login2`, send the refresh token to `token/set-cookie`, then forget it. `POST terminate` now also deletes the cookie; existing endpoints are otherwise unchanged.
- The cookie's refresh token rotates. `token/set-cookie` sets the session's next refresh token rather than the one it was sent; each `token/cookie` call sets the next. Each token is an HMAC of the previous plaintext secret, keyed from `secretBasis` (variant `refreshTokenRotation`), so the token format is unchanged. For 60 seconds after a rotation the replaced token is still accepted and gets the current one back (a lost response, or another tab's crossing request); after that, presenting it terminates the session and reports `AuthEvent.SessionRejected` with the new reason `Reused`. Older tokens are refused without ending the session. A rotating session's tokens are refused at `token/simple` and as bearer tokens (new reason `RotatingSession`; the replaced token after the grace still counts as reuse). `Session` gains nullable `previousSecretHash` and `rotatedAt` (null: not rotating; existing rows are unaffected); `previousSecretHash` is masked like `secretHash`. The exchange is public as `SessionManager.rotateRefreshToken(presented, request)`, returning a `RotatedRefreshToken(session, subject, refreshToken)`, for other endpoints that rotate. `token/simple` and non-rotating sessions behave as before.
- **Breaking:** `SessionManager.read()` no longer accepts a refresh token as a credential; a refresh token in `Authorization` gets a 401. Exchange it at a token endpoint. `acceptRefreshTokenAsBearer = Runtime { true }` (on `SessionManager` and `AuthEndpoints`) restores the old behavior for legacy clients, except for rotating sessions, whose tokens are refused.
- **Breaking:** `SessionManager.read()` accepts a token in the `Authorization` or `jwt` query parameter only on a WebSocket connect. Any other request carrying one gets a 400. The OpenAPI document no longer lists the `param` and `cookie` security schemes.
- **Breaking:** `SessionManager.read()` no longer reads the `Authorization` cookie; such a request is unauthenticated.
- **Fixed:** `HttpHeaders.Builder.setCookie` wrote `key=<name>; value=<value>; maxAge=...`, which no browser reads as the intended cookie. It now writes `<name>=<value>; Expires=...; Max-Age=...; Domain=...; Path=...; Secure; HttpOnly; SameSite=...`, and rejects an empty value, which would be written as a bare name.
- Added an **experimental** OAuth 2.1 authorization server and OpenID Connect provider, `OpenIdProviderEndpoints` (in `sessions-oauth`), so remote MCP clients (Claude and others) can get tokens for a user. Mount it at the root: RFC 8414 and OIDC metadata at `/.well-known/oauth-authorization-server` and `/.well-known/openid-configuration` (with `iss` on redirects), RFC 9728 metadata per `ProtectedResource` at `/.well-known/oauth-protected-resource/{path}`, `oauth/authorize/prepare|approve|deny` for the app's consent screen, `oauth/token|revoke|introspect` with RFC 6749 error bodies that carry no internals, and `oauth/userinfo|jwks|end_session`. PKCE S256 is required; codes are single-use (an atomic claim) and last 5 minutes; loopback redirect URIs match on any port, everything else exactly; `openid` is optional, `offline_access` is ignored, and an empty scope means the resource's scopes; the `resource` parameter (RFC 8707) limits a token to that resource's scopes, and resources can't share scopes. Clients authenticate by `client_secret_basic`, `client_secret_post`, or as public clients with PKCE alone. ID tokens are RS256, signed with `OidcSigningKey` (a base64 PKCS#8 RSA key, meant to be a setting). Consents are stored in a new `UserConsent` table. It has not been verified against the specs or with real clients: it, its models, `ProtectedResource`, and the new `OauthClient` fields require opting in to the new `@ExperimentalOauthProviderApi` (in `core-shared`, which `sessions-oauth-shared` now depends on). See the new [OAuth authorization server](docs-guide/guide/oauth-provider.md) chapter.
- An OAuth client's tokens belong to an ordinary session, tagged with the new nullable `Session.oauthClient` (existing rows are unaffected). Such a session rotates from creation (`rotatedAt` is set), so its refresh token is refused at `token/simple` and as a bearer token, even with `acceptRefreshTokenAsBearer`. The `refresh_token` grant checks the client, its allowed scopes and the requested resource, then rotates through `SessionManager.rotateRefreshToken`, with its 60-second grace and reuse detection.
- **Breaking:** typed endpoints answer refused credentials as RFC 6750 asks, so OAuth and MCP clients know to log in. No credentials is now a **401** with `WWW-Authenticate: Bearer` (it was a 403); a token that is invalid, or an `Authorization` header no reader recognizes, is a 401 `Bearer error="invalid_token"` (readers' `UnauthorizedException`s gain the header); an authenticated caller without the scopes needed is a 403 `Bearer error="insufficient_scope", scope="…"`; any other refusal stays a plain 403. Clients that treat only 401 as logged out now see a request without credentials as logged out too. Added `AuthRequirement.assert(request)`, which typed endpoints, `Request.access` and `Request.auth` now use, and `AuthRequirement.Result.Rejected.insufficientScopes` (set by the built-in requirements when only scopes were missing; `Options` sets it when every option failed on scopes). `UnauthorizedException` and `ForbiddenException` take `headers`.
- `ProtectedResource` moved from `sessions-oauth` (`sessions.openid`) to `auth` (`com.lightningkite.lightningserver.auth`), with a `protectedResources` registry that `OpenIdProviderEndpoints` fills from its `resources`. A request to exactly a registered resource's path refuses, with a 401 `invalid_token`, any token whose audience isn't that resource (checked by the new `Request.authentication()`, which `assert(request)`, `accessOrNull` and `tryAuth` use; reading `Authentication.CacheKey` directly skips it), and its challenges carry `resource_metadata` and the resource's scopes. The experimental `BearerChallenge` handler wrapper is removed: drop the wrapper (`path.post bind JsonRpcHandler(...)`), keep the `ProtectedResource` in `OpenIdProviderEndpoints`, and update its import.
- `OauthClient` gains `postLogoutRedirectUris` and `allowRefreshTokens` (default `true`). `OauthClientEndpoints.createSecret` now draws secrets from a CSPRNG (URL-safe base64) and stores them with the fast hash; secrets created earlier keep working.
- OAuth provider: a token issued for a `resource` is bound to it. `Session` gains nullable `audience` (null: this server's own API; existing rows are unaffected), set from the authorization's resource and inherited by sub-sessions; `SessionManager.newSession` gains an `audience` parameter. `Authentication` gains `audience: String?` (also on the factory and `copy`), which `Session.toAuth()` fills and masquerades keep. `PrivateTinyTokenFormat` and `PublicTinyTokenFormat` carry it in their payload. `JwtTokenFormat` writes it as `aud` (RFC 9068) instead of its `audience`, and accepts an `aud` that is its `audience` or its `audience` followed by a path. **Breaking:** a request to a registered `ProtectedResource` refuses, with a 401 `invalid_token`, any token whose audience isn't exactly the public URL plus the resource's path, including the app's own root tokens and OAuth tokens issued without `resource`. The `refresh_token` grant's `resource` check now compares with the session's audience. Tokens the released version issued still decode, unbound (see the `KotlinWireFormat` entry).
- OAuth provider: **Behavior:** a saved consent skips the consent screen only when the redirect URI exactly matches a registered `https` URI. Loopback (any port), custom-scheme and plain `http` redirects always get the screen, since any local process or app could be impersonating the client (RFC 8252 §8.6).
- OAuth provider: approving replaces the user's `UserConsent` for the client instead of adding another row (and clears the extra rows earlier approvals added). Added `GET oauth/consents` (`consentList`, a list of the new `ClientConsent`) and `DELETE oauth/consents/{clientId}` (`withdrawConsent`), which deletes the consent and ends the user's sessions issued to that client. Ending a session does not withdraw consent.
- Added `AuthEvent.ConsentGranted(principalType, principal, clientId, scopes)` and `AuthEvent.ConsentWithdrawn(principalType, principal, clientId)`, raised by the OAuth provider's `authorize/approve` and `consents/{clientId}` (only when a consent was withdrawn; the sessions it ends are each a `SessionTerminated`). **Breaking** for exhaustive `when`s over `AuthEvent`.
- `AuthEventLog` records `FactorChanged`, `ConsentGranted` and `ConsentWithdrawn`: `AuthEventRecord.Type` gains those values, and `AuthEventRecord` gains nullable `factorChange`, `oauthClient` and `scopes` (existing rows are unaffected). A released server reading the audit table fails on the new types.
- **Fixed:** `getTokenFromCookie` (`token/cookie`) and `setRefreshTokenCookie` (`token/set-cookie`) called as a `/meta/bulk` part or from server code answer 400, saying to call them directly over HTTP. Server code got a 500 (`UnsupportedOperationException`); a bulk part ran the endpoint, so `set-cookie` rotated the session and the cookie was lost with the part's headers.
- OAuth provider: revocation and introspection recognize a rotated-out refresh token within its 60-second grace as its session's (revoking it ends the session). Added `SessionManager.refreshTokenSession(token)`, which finds a refresh token's session that way without recording a use or ending anything.
- **Breaking:** `OauthClientEndpoints.rest` is now mounted at the module's path (it was built but never routed), and the client registry is readable only with `maintainPermissions` (its permissions let anyone read it).
- **Breaking:** Lightning Server's binary data moves from the positional `KotlinBytesFormat` to Service Abstractions' evolvable `KotlinWireFormat`, written from this release on; the old format, now `OldKotlinBytesFormat`, is kept only to read data written before, and goes in a release or two. Needs the Service Abstractions release with `KotlinWireFormat`. `Serialization.kotlinBytesFormat` is replaced by `kotlinWireFormat` and `oldKotlinBytesFormat` (read only), and `AnonType` takes any `BinaryFormat`. `Authentication`, `WebSocketConnectRequest` and `Expiring` give their fields `@WireId`s, so a typical root-session tiny token shrinks by about 9% (private 309 to 283 characters, public 316 to 288). In detail:
  - Tiny tokens get new prefixes: `PrivateTinyTokenFormat` writes `w/<principal>/` (was `<principal>/`), `PublicTinyTokenFormat` `tw/<principal>/` (was `tt/<principal>/`). Tokens with the old prefixes are still read, with their cache entries, in the old format. `JwtTokenFormat` writes its cache under the new claim `wireCache`, and reads an old token's `cache` claim in the old format.
  - AWS WebSocket rows store the connect request and state under new attributes, `wsWireRequest` and `wsWireState`. A row with only the old `wsRequest` / `wsState` is stale: its socket is closed and the row deleted, and the client reconnects.
  - `MultiplexWebSocketHandler` decodes binary client frames with `KotlinWireFormat`.
  - The `application/x-lightningserver-kotlin-bytes` media type keeps the old format; the new format is `application/x-lightningserver-kotlin-wire`.
  - `SerializableCache` writes entries in the new format; `SerializableCache.markEntriesAsOldFormat()` (`@InternalLightningServerApi`) is how a token reader says a cache came from an old token.
  - **Rolling deploys:** a released server can't read what this one writes. Until every instance runs this release, a released server declines new tiny tokens (401), ignores a new JWT's cache, and fails on sockets connected through a new server; a new server ends sockets a released one connected.
- `OidcSigningKey` stays a required setting: a settings file without `oidcSigningKey` fails at startup with `IncompleteSettingsException`, and the generated default only fills `settings.suggested.json` and tests. The guide now says so.

- Added a `schedules` parameter to `KtorEngine.start`, defaulting to `true`. Pass `false` when another instance runs the scheduled tasks.
- **Behavior:** the EC2 builders' systemd unit now reads its command from `SERVER_COMMAND`, defaulting to `serverCommand`. The scaling builder sets it at boot from the launch template's user data. Regenerating changes the image and launch template, so an apply re-bakes the AMI and refreshes the fleet.
- **Behavior:** `TerraformAwsScalingEc2Builder` now requires a distributed `engineCache`, the cache the schedule locks use, instead of checking the application's `cache`. A deployment with a RAM `engineCache` now fails to generate, and a RAM `cache` is allowed.
- Added `LocalEngine.onShutdown(action)`. Graceful shutdown runs the actions before disconnecting services, alongside in-flight schedule ticks and within the same drain timeout, so background work the engine doesn't manage can unwind while its services are still connected.
- Added `BuildCheck` and `ServerBuilder.buildCheck { }`: a check that runs once the whole server is built and receives the root `ServerDefinition`, even when registered in a module. Modules' checks run first. It has no runtime and is not kept on the definition. Throw from it to fail the build.
- **Behavior:** the notification registration checks (every event has content and subscriptions) are now build checks, so a missing registration fails `build()` instead of server startup. The `/verify` startup tasks they replaced are gone.
- **Breaking:** removed `PathSpec0.include(ServerDefinition)`, the SDK's `PathSpec0.module(SdkModule<ServerDefinition>)` and `ServerDefinition.withSdkInfo`. Include the `ServerBuilder` instead.
- Added `ClientTelemetryEndpoints` (typed): `POST ingest` takes a `TelemetryBatch` of spans and logs recorded by a client app (e.g. KiteUI) and hands it to the server's telemetry backend, so client builds carry no telemetry credentials. Mount with `path.path("telemetry") module ClientTelemetryEndpoints(cache)`; the generated SDK calls it `clientTelemetry.ingest`. Anonymous callers are accepted. The server sets the records' identity: `service.name` is `<projectName>-client`, `user.id` comes from the caller's authentication, and only the allowlisted client resource keys (`ClientTelemetryEndpoints.CLIENT_RESOURCE_KEYS`: `service.version`, `os.type`, `session.id`, `app.debug`) are kept; client-sent `user.*` attributes are dropped. Uploads are rate limited per signed-in user, else per IP (`RateLimitInterceptor`, state in `cache`): a burst of about 24, then one per 5 seconds. Setting `clientTelemetryRateLimit` to null turns that off. Ingested spans feed no metrics. Rejected whole with 400 (not truncated): batches over 2000 records, records over 128 attributes, attribute values over 4096 characters, malformed trace/span ids, and owner/attribute names not matching `[A-Za-z][A-Za-z0-9_.-]{0,63}`. The ingest request itself isn't traced.
- `typed-shared` now depends on SA `telemetry-shared` (`api`), so clients get the SDK's `TelemetryBatch` without `basis`.
- Added `HttpHandler.traced` (default true). A handler that returns false gets no request span and no RED metrics, and nothing beneath it is traced (SA's `Untraced`).
- Added `PinBasedProofEndpoints.ScreeningResult` (`Allow`, `Suppress`, `Reject(message, detail)`) and an open `PinBasedProofEndpoints.screen(to)` hook, called before a PIN is created. `start` responds 400 with the given `message` and `detail` (default `"target-rejected"`) on `Reject`, and lists that error in its `errorCases`.

A deprecated `EmailProofEndpoints(..., verifyEmail = ...)` overload maps `true`/`false` to `Allow`/`Suppress`.

It is nullable so Postgres can add the column to an existing session table.

The `Authentication(principalType, subject, ...)` and session `Authentication(..., sessionId: Uuid?, ...)` factories and `testAuth` keep their `issuedAt` parameter, which now sets `sessionIssuedAt`.
- Added `Authentication.tokenIssuedAt: Instant?`, when the access token was minted (null when the authentication didn't come from an access token), and a `tokenIssuedAt` parameter on the factory and on `Authentication.copy`. All built-in token formats set it on `create`.

### Behavior

- `RateLimitInterceptor` checks and charges each request a client made on its own: requests the engine received, each `/meta/bulk` part, and each socket connect, multiplexed virtual sockets included. Internal endpoint calls are no longer charged separately, and later socket phases never are. Pass your `MetaEndpoints`' `bulk` in `exempt` and the `MultiplexWebSocketHandler` in `exemptSockets`, or the wrapper is charged as well as its parts. A 429 carries `Retry-After` and the rate-limit headers, and a bulk response reports the furthest any of its parts reserved or was told to wait.
- A request `RateLimitInterceptor` rejects is charged `borrowTime`, so a caller retrying more often than that while blocked stays blocked. Its cache entries now live until they fall `leeway` behind, instead of a fixed 15 minutes that forgave larger debts.
- An exception thrown by an `ExecutionInterceptor` during an HTTP execution goes through the server's exception handler, so an `HttpStatusException` keeps its status instead of becoming a bare 500. When it is thrown before the HTTP chain ran, the error response still runs through that chain and gets CORS and security headers.
- The `X-Masquerade` value is also read from a query parameter of the same name (ignoring case, like the `Authorization` fallback) when the header is absent, so WebSocket clients, which cannot set headers, can masquerade.
- **HTTP request and WebSocket connect spans continue the caller's trace.** A W3C `traceparent` request header becomes the parent of the request's root span, so client and server spans share a trace. If CORS `limitToHeaders` isn't `*`, add `traceparent`.
- **Email and SMS proof screening runs before the PIN is created.** Previously the PIN was created and the `verifyEmail`/`verifyPhone` check ran afterward in `send`. Suppressed requests still create a PIN, so their lookup key behaves exactly like a real one. Invalid email addresses passed to `EmailProofEndpoints.start` now respond 400 before screening.
- **Security: sub-sessions no longer reset the re-authentication clock.** A sub-session inherits its parent's `authenticatedAt`, so `maxAge` requirements (e.g. the 10-minute gate on proof-method credential management) measure time since the user actually proved identity rather than since the sub-session was minted.
- **Security: sub-session scopes must be within the parent's.** `POST /sub-session` now responds 403 when the requested scopes are not all met by the parent session's scopes, and 401 when the parent session has been terminated. Omitting `scopes` (the default, root) now grants the parent's scopes rather than root, so callers of a narrower-scoped session that omit scopes keep working.
- **Opt-in access token revocation.** With `tokenInvalidationChecks = true`, terminating or deleting a session through the session table rejects the live access tokens of it and every session derived from it, and `invalidateSession` / `invalidateSubject` reject a session's or subject's current access tokens. Invalidations live in the cache for one token lifetime; each access-token request reads the cache once or twice and fails if the cache does. A JWT minted in the same second as an invalidation, just after it, is also rejected, because JWT times are whole seconds. Sessions last used more than one token lifetime ago get no cache entry. A cache failure while recording a termination's invalidations is logged and does not stop the termination or its cascade.
- **JWT claims changed.** `iat` is now when the access token was minted (it used to be when the user authenticated), and the authentication time moved to the new `siat` claim. A JWT whose `prn` is not the reading principal's name is ignored (read returns null), and audience or issuer mismatches now throw `JwtException` instead of being ignored. Malformed JWT payloads throw `JwtFormatException`, and the signature is now verified before the claims are parsed.
  - **Upgrading:** access tokens minted before this release are not accepted. JWTs have no `prn` and are ignored, so those requests are unauthenticated. Tiny tokens are expected to fail to decode and get a 401, since the encoded `Authentication` changed shape. Clients get a new access token on their next refresh.
- **Sign in with Apple now passes the user's verified email to `ExternalProfile`.** It was always null before, because the `email` and `email_verified` claims were dropped while decoding the ID token.
- **Tiny tokens that decrypt or verify but don't decode now throw `TokenException`** (a 401) instead of an arbitrary serialization error.
- **Terminating a session terminates its derived sessions.** Terminating or deleting a session through the session table (`sessionInfo.table()`, `table(auth)`, the logout endpoints, a superuser's REST update or delete) now also terminates every session transitively derived from it. Writes through `sessionInfo.baseTable()` or straight to the database do not cascade. Sub-sessions no longer outlive their parent's logout; use a separate session for integrations that must.
  - **Upgrading:** this only applies to terminations from now on. Sub-sessions whose parent was terminated before this release, and sub-sessions minted earlier with broader scopes than their parent, stay valid. To clear them, terminate every existing sub-session once after deploying:
    ```kotlin
    sessions.sessionInfo.table().updateMany(
        condition<Session<User, Uuid>> { (it.derivedFrom neq null) and (it.terminated eq null) },
        modification { it.terminated assign now() },
    )
    ```
- **`Session.derivedFrom` is now indexed** (`@Index`), so the cascade doesn't scan the session table. Mongo creates the index on the collection's first use after deploy; Postgres adds it via its additive schema preparation.
- **Security: fixed reflected XSS in `/meta/ws-tester`.** The `path` query parameter was interpolated raw into the page's HTML; the page's script now reads it from `location.search` and assigns it to the input's `value`. The page's Connect action also ignores paths not starting with `/`, so a crafted `?path=@evil.example/x` link can't send the user's token to another host. The page is also served with `Content-Security-Policy: frame-ancestors 'none'` so it can't be framed for clickjacking.
- **Security: masquerading no longer resets the re-authentication clock.** The `X-Masquerade` authentication now keeps the original authentication's `sessionIssuedAt`, so an old token plus the header no longer passes `maxAge` requirements.
- **`/meta/openapi` (Swagger UI) loads the spec from `openapi.json`** instead of inlining the JSON into a `<script>` block, so descriptions containing `</script>` can no longer break out of it.
- **HTTP root span uses route pattern.** `ServerRuntime.handle()` now creates a single root span named `"<METHOD> <route-pattern>"` (e.g. `GET /users/{id}`) at the top of the handler, with standard `http.*` attributes. The previous `handleWithMetrics` helper has been folded into `handle()`; metrics recording, exception handling, and gzip negotiation all happen inside this root-span scope, so interceptor and exception-handler spans nest correctly.
- **Unmatched HTTP requests are now traced.** They produce a root span named after the literal target instead of being silently uninstrumented.
- **HTTP metrics on the exception path now carry the real route.** The route pattern is resolved once at the top of `handle()` and reused for both success and failure metrics/spans, so failed requests no longer record `route = "unknown"`.
- **Ktor WebSocket lifecycle is now traced.** The Ktor engine routes `willConnect` / `didConnect` / `messageFromClient` / `disconnect` through the `*WithMetrics` wrappers, matching the instrumentation of the other engines.
- **Scheduled tasks emit OTel spans.** `LocalEngine` now wraps scheduled-task polling and execution in `schedule.poll <name>` and `schedule.tick <name>` spans, with `schedule.name` and `schedule.lockHeld` attributes.
- **Security:** with `realIpHeader` set, the Netty, Ktor and JDK engines use the right-most entry of the header (the address the trusted proxy appended) instead of the whole value. Clients could previously spoof their IP through `X-Forwarded-For`, which affected rate limiting and audit.
- **Security:** `Signer.verify(String, String)` and `verifyBlocking(String, String)` now Base64-decode the signature, so they verify what `sign(String)` returns (previously they always returned false).
- `AwsAdapter` loads settings from the Secrets Manager secret once. It no longer falls through to the bundled file and S3, which loaded settings twice or crashed.
- `SecretBasis` rejects values shorter than 64 bytes with a clear error, `toString()` no longer prints the secret, `SecretBasis()` generates exactly 64 bytes, and `BASE64_CHARS` is corrected to 88.
- `OauthProofEndpoints` fails at the callback with a clear `IllegalStateException` when `makeProof` proves a property other than the declared one. Before, login rejected the proof.
- `doOnce`, and so `startupOnce` and `predeployOnce`, now rethrows the action's failure after recording it, instead of logging and returning. A failed `predeployOnce` fails the deploy, and a failed `startupOnce` fails startup. A later run still retries.
- Local engines (Netty, Ktor, JDK): a schedule whose tick throws now waits for its next scheduled run instead of rerunning immediately in a tight loop. A task's own timeout no longer stops its schedule.
- `NettyEngine` now applies `webSocketSettings.ping` and `pongTimeout` like `KtorEngine`: an unanswered ping closes the socket with 1011 "Ping timeout".
- `CronPattern.toString` writes day-of-week as Sunday=1 … Saturday=7 (Quartz/EventBridge). AWS Lambda weekday cron schedules were off by one day.
- `TerraformAwsScalingEc2Builder` rejects a RAM `engine-cache` (`ram`, `ram-unsafe`). It used to check a setting named `cache`, so the check never applied.
- `FullyCustomizableSubscriptions` default subscriptions keep `FullEventSubscription.inApp` (it was dropped, so in-app was always immediate), and `UpdateRetainingUserChanges` updates `inApp` like the other channels.
- `refreshNotifications` also sends notifications whose in-app delivery came due, so a delayed in-app-only notification is marked sent instead of staying unsent.
- `AnnotationValidators.StandardWithExternalModule` and `StandardWithInternalModule` now use the module they are named for; they were swapped.
- Typed GET/HEAD input (`HttpRequest.queryParameters(serializer)`) is decoded with `externalSerialization`, like request bodies, instead of `internalSerialization`.
- `QueryParameters.parse` URL-decodes keys and values, and `QueryParameters.toString` URL-encodes them, as their KDoc said. `/meta/bulk` sub-request query strings are now decoded. WebSocket connection rows stored by an older version whose query values contain a raw `+` or `%` decode differently.
- With no media coders registered, `HttpExceptionHandler.Default` answers in plain text with the error's real status instead of a bare 500. An exception handler that throws is now logged and reported instead of being swallowed.
